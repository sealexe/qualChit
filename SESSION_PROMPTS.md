Черновики стартовых сообщений для двух первых сессий. Используй CLAUDE.md как контекст проекта (Claude Code подхватит его автоматически, если файл лежит в корне проекта) — в промтах поэтому не дублирую то, что уже там написано, а фокусируюсь на конкретной задаче сессии.

## Сессия 1: генерация начальной файловой структуры

```
Прочитай CLAUDE.md в корне проекта — это контекст всего проекта.

Сейчас задача: создать начальный каркас файловой структуры проекта,
без бизнес-логики. Нужны:

1. Корень проекта с двумя подпроектами: frontend/ (React) и backend/
   (Node.js + Express).
2. frontend — стандартный React-проект Vite,
   с CSS-модулями уже подключёнными.
3. backend — Express-приложение с минимальным "hello world" роутом,
   готовое принимать multipart/form-data (для будущей загрузки файлов).
4. Папка library/ в корне (или в backend/ — предложи, где логичнее), со структурой:
   library/ВИК/, tlibrary/РК/, library/УК/
5. Папка transformers/ в backend для будущих изолированных модулей
   трансформации документов — пока пустая, с README.md, объясняющим
   принцип "один модуль = один тип документа".
6. .gitignore (node_modules, build, временные файлы загрузок и
   сгенерированные архивы).
7. Корневой README.md с кратким описанием проекта и тем, как запустить
   frontend и backend локально.

Не пиши пока никакой бизнес-логики (ни форму, ни обработку файлов) —
только структура и заглушки. После каждого крупного шага коротко
объясни, что создано и зачем, простыми словами — я начинающий
разработчик.

В конце выведи дерево созданной структуры и список команд для запуска.
```

## Сессия 2: генерация фронтенда (форма ввода данных)

```
Прочитай CLAUDE.md в корне проекта — это контекст всего проекта.
Файловая структура уже создана (frontend/, backend/, templates/).

Сейчас задача: реализовать ТОЛЬКО фронтенд — форму ввода данных,
без интеграции с backend (отправку данных на сервер пока не делаем,
максимум — console.log по кнопке "Сгенерировать").

Форма, один компонент Form (или несколько подкомпонентов, если так
понятнее для чтения — на твоё усмотрение, но без избыточного
дробления), со следующими полями и порядком (каждый пункт — отдельная
"строка"/секция формы):

1. Фамилия Имя Отчество — текстовое поле, обязательное.
2. Метод контроля (выпадающий список: ВИК, РК, УК — оставь возможность
   легко добавить новые методы списком в одном месте кода) и рядом
   № образца (текстовое или числовое поле) — на одной строке.
3. Дата экзамена — date picker (стандартный input type="date" будет
   достаточно для начала).
4. Блок "Комиссия" с тремя полями подряд:
   - Председатель
   - Эксперт
   - Технический эксперт
   (каждое — текстовое поле, ФИО).
5. Drag&drop зона для загрузки файлов:
   - поддержка перетаскивания файлов и обычного выбора через клик
   - показывать список уже выбранных файлов с возможностью убрать
     файл из списка
   - можно загружать несколько файлов
6. Кнопка "Сгенерировать":
   - неактивна, пока обязательные поля не заполнены
   - по клику пока просто выводит собранные данные формы в консоль
7. Область "Скачать архив":
   - пока просто плейсхолдер-блок (скрытый/неактивный), который мы
     наполним логикой в следующих сессиях, когда появится backend

Используй CSS-модули для стилизации, простую и аккуратную вёрстку без
лишних UI-библиотек. Валидацию полей делай простую (required + базовые
проверки), без сложных схем валидации на этом этапе.

Делай компонент частями: сначала структура и состояние формы (useState),
потом стили, потом drag&drop, потом валидация и блокировка кнопки.
После каждой части — кратко объясни, что добавлено и как это работает,
я начинающий разработчик и хочу понимать код, а не просто получить
готовый результат.
```

## Заметка по работе с этими промтами

- Запускай их как отдельные, последовательные сессии — не объединяй в одну.
- Перед стартом сессии 2 убедись, что структура из сессии 1 действительно создана и приложение запускается.
- Если в процессе сессии Claude Code предлагает забежать вперёд (например, сразу подключить backend во время фронтенд-сессии) — можно явно останавливать и просить вернуться к рамкам текущей задачи.
