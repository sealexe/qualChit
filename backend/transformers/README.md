# Transformers

Здесь живут модули трансформации документов.

## Принцип: один модуль = один тип документа

Каждый тип документа (конкретная заготовка из `library/`) обрабатывается
своим **отдельным файлом**. Никакой общей функции "на все случаи",
которая внутри разбирается, какой это документ и что с ним делать.

Например:

```
transformers/
  vik-protocol.js   # протокол ВИК
  rk-act.js          # акт РК
  uk-protocol.js     # протокол УК
```

Почему так:

- Если в заготовке поменялся плейсхолдер или формат — правим один файл,
  не боясь сломать остальные документы.
- Легко добавить новый тип документа, не трогая существующие.
- Каждый модуль можно прочитать и понять отдельно, без контекста всего
  проекта.

## Договорённость о входе/выходе

Каждый модуль-трансформер принимает данные формы (объект с полями —
ФИО, метод контроля, дата, состав комиссии и т.д.) и путь к
файлу-заготовке, а возвращает путь к готовому файлу.

Точную сигнатуру функции зафиксируем, когда будем делать первый
трансформер (шаг 4 в CLAUDE.md).

Общая логика вызова LibreOffice (конвертация/заполнение) выносится в
отдельный сервисный модуль вне этой папки — трансформеры им
пользуются, а не дублируют вызовы самостоятельно.
